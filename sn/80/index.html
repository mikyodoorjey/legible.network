The work

A fine-tuned robot control model, uploaded whole to Hugging Face. Miners start from the season's base model (LingBot-VLA 2.0 for simulation since 2026-09-01), train it by any recipe, publish the complete merged checkpoint, pay a fee in TAO, and announce the Hugging Face commit on chain. Every submitted model is public and free to download.

own docs · raw.githubusercontent.com

publish their fine-tunes as complete model checkpoints on Hugging Face

How it is scored

A benchmark worker runs each checkpoint through LIBERO manipulation tasks in the MuJoCo simulator, seeded from the commitment's block hash plus a drand beacon. The score is the average success rate. Ranking is king-of-the-hill: a challenger takes the crown only if its score exceeds the champion's by more than 0.01; a tie loses and the challenger is left off the board. The evaluation code is in a separate repository.

own docs · raw.githubusercontent.com

the challenge succeeds only if challenger_score > champion_score + champion_margin (default 0.01)

Sources disagree The overview at the pinned commit says the round scores six LIBERO suites for a pi0.5 base; the live competitions API on 2026-09-19 names the simulation benchmark libero_pro_custom_1 with a LingBot-VLA 2.0 base and a baseline of 0.285833 over 5 trials.

How the pay splits

Three pools. Simulation takes 15 percent of the miner share and pays only its top three at 70, 20 and 10 percent of that. Each of two real-robot tracks on an xArm 6 takes 42.5 percent, settled once a season: 95 percent to the single champion vested over 120 days, 5 percent shared by entries clearing the qualification bar. Live weights on 2026-09-19 read 0.425, 0.425, 0.105, 0.03, 0.015.

Who judges

Nine validators were active on the 2026-09-09 chain snapshot, of 64 permitted. Weights are committed then revealed, at most once per 100 blocks. Validators do not run the benchmark: validator.py reads a settled weight vector from the operator's backend API with a read-only key, normalizes it and calls set_weights. The evaluation itself runs on the operator's benchmark workers.

How often it turns

Emission settles every 360 blocks, about 72 minutes. The validator's default is to set weights every 720 minutes. The simulation board turns per submission: a checkpoint is scored when it reaches the front of the queue and the champion holds until beaten. Real-robot tracks run as seasons of roughly a month, with fixed submission and evaluation windows. A new registration is immune for 5,000 blocks, about 16 hours.

tempo 360, immunity_period 5000; validator.example.yaml weight_interval_min: 720

Who buys

Nobody is named. The front page describes a competition whose winning model becomes the next base, and every checkpoint is public on Hugging Face. The competitions API lists fees paid by miners, 0.1 TAO burned for simulation and 1.5 TAO transferred for a real track, and no price for anyone else. I found no customer, product or usage figure on the site, in the API or in the repository.

What has been gamed

The overview records a red-team study: the four base LIBERO suites could be saturated for about $50 of GPU time by memorizing public demonstrations, so two swap-perturbation suites were added. Other named attacks and answers: queue flooding, met by the burn fee and one commitment per hotkey per round; copying the champion, met by the tie-loses margin; resubmitting another miner's weights, met by shard fingerprinting; replayed burns, a 10-block window.

Explained from zero · training · written 2026-09-10

SN80 OpenRoboto runs a sheepdog trial for robot brains, where every handler trains a pup from the same litter, the course is unseen until the day, and the champion keeps its place until a dog clearly beats it.

The commodity, explained from zero

The output is a model checkpoint: a saved file of a robot's control brain, the kind downloaded to make a robot arm pick things up when told to in plain English. These are called vision-language-action models because they take in camera images and a text instruction and put out arm movements, as a sheepdog takes in a field and a whistle and puts out a run. The subnet starts from a public base model, the shared litter, and pays people to train a better dog from it. Miners "Fine-tune the official base model" and then "Publish a complete merged checkpoint to Hugging Face and submit on chain."

The strongest robot models today, the front page says, "are built inside a few private labs." Whether anyone will pay for an open one is unstated. No customer is named; the only hint at a buyer is a front-page line about hosting a "policy tournament based on real factory need." The champion's file is public on Hugging Face, so a buyer would pay nothing to download it.

Why it is on Bittensor at all

What the network adds is an open, checkable scoreboard and a purse. Anyone can enter, the course is drawn from randomness no handler can predict, and every score comes with an audit record. Here the comparison breaks: a champion sheepdog goes home with one handler, while here the champion is a file anyone can copy, and the prize is the subnet's token, vesting over 120 days.

How the work gets done

Miners fine-tune the season's base model (LingBot-VLA 2.0 this season), upload the full checkpoint, pay a fee in TAO (0.1 burned for the simulation track, 1.5 transferred for a real-robot track), and announce the submission on chain. Validators run each checkpoint through LIBERO manipulation tasks in a physics simulator, a trial field made of software, with test seeds derived from the block hash plus drand, a public randomness beacon, so they are "unpredictable before submission, frozen after it, and reproducible by anyone." A challenger wins only if its score exceeds the champion's by more than 0.01; a tie fails. Emission, the subnet's share of newly minted TAO, is split 15 percent to the simulation board and 42.5 percent to each of two real-robot tracks on an xArm 6, the trials run on a real field, where 95 percent of the track's pool goes to the single champion.

How you would know it works

The public competitions API at https://api.openroboto.ai/api/v1/competitions lists three active competitions, their fees, and a simulation baseline score of 0.286. The leaderboard at https://www.openroboto.ai/#/benchmark renders only with JavaScript; the index's fetch on 2026-09-09 saw a champion at 0.841.

What is missing

There is no product, price, or API for buyers, and the on-chain contact riccardo@openroboto.ai appears nowhere on the site or in the repositories. The chain's github_repo README calls its own submission flow deprecated and points to a second repository. The site is an empty page without JavaScript. No Discord is set on chain; support is "Open an issue on GitHub."

What 3.3 means

OpenRoboto pays people to train robot brains: models that turn a camera image and a plain instruction into arm movements. A miner with one graphics card can enter for a fee and split the prize; anyone can download the champion free. A current guide makes the contest easy to follow, but buyers find no product, price, or contact.

  • If you were a staker 3.3 You could read a named document on how cheating is blocked and see a dated leaderboard, but you would need Bittensor knowledge, and no page names a customer or gives revenue.
  • If you were a miner 4.0 You could learn what to train, the graphics card you need, the fee to enter, and how the top three split the prize, from a guide updated this month.
  • If you were a buyer 2.0 You could download the open models, but you would look for a customer type, a price, or a support address and find only an invitation to open an issue.
  • If you were a newcomer 3.8 You could read on the front page that models are built in the open instead of inside private labs, and see a dated leaderboard, if your browser runs scripts.
