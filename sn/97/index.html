Explained from zero · training · written 2026-09-10

SN97 Albedo is a playground game of king of the hill for coding models, where one fine-tuned model stands on top and earns most of the prize until a challenger knocks it off by a clear margin, twice.

The commodity, explained from zero

The output is a model checkpoint: a saved copy of an AI model's weights, the file needed to run it. Every entrant climbs from the same flat ground, the open model Qwen3.6-35B-A3B, and fine-tunes it, meaning they train it a little further on their own data for one job. The job here is acting as a coding agent: reading a real software repository, running commands, and making edits over several turns. The materials call the recorded runs "trajectories" and the method "trajectory distillation", a term they do not define (inferred from the scoring doc: learning from example runs of a stronger model).

A better coding-agent model could have a price, but Albedo's materials name no buyer, no price, and no unit of sale. The only public use is a "Chat with the King" link to the current champion. For someone to pay, the champion would have to beat the models they already rent; the site's benchmark panel should show that but rendered only "loading" when fetched.

Why it is on Bittensor at all

The honest answer is: an open contest with a public ledger. Anyone can register, upload a fine-tuned model to a file host, and commit a fingerprint on chain; the king is chosen by a fixed procedure rather than a lab's release schedule. The materials do not compare this with a centralized provider on cost, ownership, or censorship. Here the comparison breaks: on the playground, holding the hill is the whole point, but here the model on top is supposed to be the product, and nobody has said who wants it.

How the work gets done

Miners fine-tune the base model, keep its configuration files identical to the original, and publish it; a duplicate check rejects copies and lightly noised copies of earlier entries. Validators, the judges who set pay, run the challenger and the reigning king on the same hundred coding tasks from real repositories, then ask a judge model (GLM 5.2) a checklist of yes-or-no questions about each run; a run that loops on one command scores zero. A challenger takes the hill only if it beats the king by 2.5 points in two separate evaluations. Emission, the subnet's share of new tokens, is split across the current king and the previous four in a rolling chain, so a king pushed off the hill fades out rather than dropping to zero.

How you would know it works

No artifact a reader can check exists today, in those words. The dashboard at albedo.tech lists benchmarks, reign, queue, history, and fails, but each section shows "loading…" to a fetcher, and the chat link opens a chat app that explains nothing.

What is missing

The chain description is two words, "Alchemical intelligence". The repository has no README; the guides sit in a docs folder nothing links to. The chain contact appears on no page. There is no price, customer, status page, or support path. The win margin is 2.5 percent in the guides and 3 percent in the site's llms.txt, a file written for AI agents. Registration cost and miner hardware are not stated.
